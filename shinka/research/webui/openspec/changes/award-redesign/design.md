### 颜色

对比度按 WCAG 2.x 相对亮度公式对色值核算，括号内是该色在 `bg`、`rail`、`raised`、`hover`、`selected` 五种底色上的最小–最大值；图表只画在 `bg` 与 `rail` 上，得分色阶的下限按这两种底核算。要求：正文与小字至少 4.5:1；坐标刻线、输入框与复选框边框、选中指示和图中数据标记至少 3:1。色值核算不等于整页无障碍认证，渲染后的页面另行实测。

### 字体与数字

- 界面 Inter Variable，数字、编号与代码 IBM Plex Mono，均本地打包；中文回退 PingFang SC、Microsoft YaHei、Noto Sans SC。
- 字号：页面标题 26/34（590），数据句标题 30/40（600），区块标题 15/22（590），正文 13/20，小字 12/18，数字 12–13 tabular 右对齐。
- 格式：分数与 Sharpe 两位小数，DSR 三位，金额 `$0.00`，时间 `YYYY-MM-DD HH:MM` 并标注 UTC，缺失 `—`，明确记录的零显示为零。负号用减号 U+2212；差值按显示精度相减，使“较父代”与两侧显示值一致；不足半分的金额显示 `<$0.01`（待所有者确认）。含费用未知运行的合计前加 `≥`，表示下限。`≥`、`≤` 取系统字体，因为打包的拉丁子集没有这两个字形。

### 空间与形状

4px 基线；间距 4、8、12、16、20、24、32、40。控件圆角 6px，浮层 8px；表格、面板、卡片与代码和日志块不加圆角，以发丝线分隔，不用阴影分层。

### 状态

假设状态用形状加文字，从不只靠颜色；用词固定为 待跑、已选、运行中、待判定、成立、否定、未定、已确认、未确认、放弃（与当前 `app/src/format.ts` 一致）。桌面表格单元格显示形状、文字与计数；图例只作补充。英文界面对应 queued、selected、running、challenged、supported、refuted、inconclusive、confirmed、unconfirmed、dropped。

方向状态用方形，假设状态用圆形，两者不共用形状：进行中（方框内一个实心小方块）、已结论（实心方框加勾）、新建（虚线方框）、超预算（方框加斜向箭头，信号橙）。事件同样用形状加事件词：＋ 搭建实验、■ 运行完成、✕ 运行失败（信号橙）、◇ 质疑检验、◆ 判词、△ 试探、开锁图形 封存段确认。

### 控件状态

选中状态不只靠底色：导航当前项与视图页签加 2px `text` 色指示条，分段控件（主题、语言）的选中段用 `text` 文字加 1px `stroke` 描边；运行表勾选框与输入框的边框用 `stroke`；带文字的按钮只用 `line-strong` 发丝边，由文字标识控件。焦点环为 2px `text` 色外描边，在选中底上仍有 13.36:1（深）与 14.36:1（浅）。

### 图表语法

- 全部为 SVG/D3，颜色取自 token；3D 聚类是按需加载的 Canvas 2D 投影。
- 要互相比较的图共用刻度并标注刻度值：首页证据刻度各行共用一把尺（刻度间距不足 44px 时隔一个标注）；进展小图组共用横轴（代数）与各自标注的纵轴；多运行比较的运行级指标每行自带刻度，并在表头注明“本行刻度”。
- 噪声线由图表本身绘制；试验序号与代数只出现整数刻度；纵轴下端对齐到带标注的刻度，上端贴着数据。
- 噪声线母题：报告的试验图与进展的累计最佳在末端用橙色括号标出最佳记录越过噪声线的幅度（如“越过 +0.37”）；首页证据刻度用同一编码：菱形为最佳记录，竖线为当时的噪声线，橙段为越过的部分。
- 评估失败单列一条“失败带”（报告试验图与进展在得分轴下方，解空间按 PCA 1 位置排在散点下方），计入总数、不计入最佳与前沿，不画在 0 上。
- 得分色阶的定义域取有效分数的第 5 百分位到最大值，更低的分数取色阶最暗端，图例标 `≤`。
- 多个运行用形状加线型区分（● 实线、□ 虚线、▲ 点线），线的终点直接标注运行与数值；表格里“本行更优”用加粗表示，不另加符号（三角已是运行的形状），显示值相同则并列。
- 图中任何悬停信息都能通过点按或聚焦在检查器中读到。

## 联动与选择

分析页共享一个选择模型：`{ run, tab, program, generations, filters, pane }`，全部写入 URL。任一视图选中程序只更新检查器，并在其他视图高亮同一程序及其祖先路径，不切换当前视图（OD-11）。顶栏下的运行条（运行路径、程序、有效、失败、代数、岛数、费用）在四个视图中相同。谱系与进展共用代数轴和同一个代数滑杆组件（上一代、下一代、回放）；回放只在点击播放时按代步进，到最后一代停止（OD-8）。

检查器标签页：代码、差异、评估（输出与图像，失败明确标注）、LLM 记录、元分析总结（OD-3），以及纯文本下载（OD-12）。检查器是桌面右侧栏（≥1440 宽 440px，1024–1439 宽 380px）；不做手机底部抽屉（`owner-decisions.md` › 手机）。

## 动效

静态姿态：没有入场动画，内容不被入场效果隐藏；状态变化即时完成；悬停与焦点只改变颜色或描边。代数回放是用户触发的离散步进，不做插值；系统要求减少动态时，回放改为每次点击前进一代。

## 无障碍与国际化

- 键盘：Tab 顺序与视觉顺序一致；表格行可用方向键移动、回车进入；Ctrl K 打开命令面板；Esc 关闭浮层与抽屉；焦点环用 `text` 色 2px 外描边。
- react-aria-components 提供页签、术语提示、浮层与对话框等交互组件的 ARIA 与键盘行为；外观全部来自项目 token 与项目样式，不加载组件库样式。
- 中英切换覆盖全部界面文字、状态词、日期说明与图表标注；研究内容（假设标题、日志正文、LLM 输出）保持原文。默认语言暂按 grill.md:10 取中文，待所有者在高保真评审时确认。

## 数据接口

- `/api/workspace` 为每个成功方向增加只读 `evidence`（假设状态计数、最佳样本内分数、当时噪声线、`evaluated_programs`、`failed_programs`、最近活动）与 `unknown_cost_runs`；`/api/snapshot` 的方向带 `unknown_cost_runs`，每个实验带 `spend_known`。首页不再逐方向请求 `/api/snapshot`（`research-workspace-ui` 规格）。
- 费用口径（OD-9）：`shinka.database.cost` 是唯一规则，研究层经 `rundb.run_cost` 使用；预算检查、授权运行的上限、工作区接口、方向快照、`/get_database_stats` 与运行器续跑的起点都用它（`run-analysis-ui` › 运行费用只有一个口径）。它计非岛副本的程序、`attempt_log` 中没有成为程序的已付费工作（耗尽尝试的提案、到达目标后丢弃的提案、没有存下提示词的提示词进化）与提示词进化。缺失或为 null 的费用字段按 0 计，因为运行器只为执行过的步骤写字段（`meta_cost` 只写在元分析计费的程序上）。出现的值必须是有限且不小于 0 的数；headless 模型带 `headless_pricing_unknown` 时该程序费用未知，与 `dbase.py` 的人口遥测一致；运行器写不进的费用留下 `cost-unrecorded.json`，该运行的合计从此未知。单个未知运行显示“—”，含它的合计按 `recorded_cost` 求和并显示 `≥` 下限。研究实验的运行拒绝 headless 模型（`cli.py` 的 `cmd_run`：`--set` 传入的与 `shinka.yaml` 中配置的都拒绝），所以研究方向的花费在数据完好时是精确值。
- `/api/snapshot` 的 `trial_points` 增加程序编号，供试验点打开检查器（OD-18）；验证段与封存段数字仍按规则隐藏。
- 分析数据沿用 `analysis.py` 的只读接口（`/list_databases`、`/get_programs`、`/get_program_details`、元分析与图像），路径约束、私有指标隐藏与错误语义不变；只在新视图确需时增加只读聚合接口。

## 迁移与删除
