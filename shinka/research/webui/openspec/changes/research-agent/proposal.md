# 内置对话 Agent（research-agent）

## 为什么

所有者 2026-10-20 提出：「另外我想内置一个对话AGENT可以帮我持久化操作盯着」。研究 Agent 本身已经存在：`skills/shinka-research/SKILL.md` 规定了轮次流程、检查点、封存段与预算规则，`shinka_research brief` 是给 Agent 的进展摘要（`cli.py:380-414`），每个运行事件写入 `results.tsv`（`cli.py:197`）。缺的是四件事：

- **运行随窗口一起结束。** `cmd_run` 阻塞在 `subprocess.call`（`cli.py:185`），状态只在 `finally` 中恢复（`cli.py:186-194`）；终端被关闭时运行随之中止，假设可能停在“运行中”。
- **授权只是约定。** 2026-10-18 所有者确认：Agent 做完授权的这一轮就暂停，故障只在既定条件、预算和尝试次数内处理，开下一轮与开封存段需要所有者明确同意。代码里没有轮次授权与尝试次数，封存段只靠 `--yes`（`cli.py:285`），模板的 `autonomous` 模式“跑到预算用完”（`cli.py:61-62`、`SKILL.md:37-41`）与这条规则冲突。
- **多个写入者会互相覆盖。** `Notebook.save` 是不加锁、非原子的 `write_text`（`notebook.py:109-110`）；`cmd_probe`、`cmd_confirm` 在长时间评估后保存旧副本（`cli.py:220-231`、`276-309`），可能覆盖另一个运行刚写入的 `n_evaluated`。DSR 不受影响，质疑检验按运行库重算试验数（`skeptic.py:171-185`）；受影响的是 `brief` 与 `status` 报的试验数（`cli.py:388`、`420`），它读的正是这个值，而且运行中的实验要等运行结束才写入；`brief` 是 Agent 每轮先读的进展摘要。工作台已改为按运行库计数（award-redesign）。
- **没有人盯。** `shinka/research/` 中没有轮询、提醒或后台进程；研究界面服务随 `ui` 命令进程结束（`ui.py:369-377`）。

## 所有者决定（2026-10-20）

| 事项 | 决定 |
|---|---|
| 在哪里对话 | 「1+2」：工作台里的对话页，以及 Tern 终端里的 omp |
| 持续程度 | 「开着时才盯」：终端或网页开着时盯，关掉后再打开补查一次；研究运行转到后台，关窗口不会中断 |
| 两边对话 | 共用运行记录、已批准的轮次与待决事项；两边对话各自独立 |
| 在哪里批准 | 网页和终端都能批准，包括打开封存段；Agent 只能申请 |
| 授权边界 | 沿用 2026-10-18 规则：做完授权的这一轮就暂停；故障只在既定条件、预算和尝试次数内处理；不改冻结的数据与评估器，不重置计数与预算；开下一轮、开封存段要所有者明确同意 |

## 改什么

- **规则落进 `shinka_research`：** 笔记本加文件锁与原子保存；运行可脱离窗口在后台继续，带运行租约，`watch` 负责重开后对账；`probe` 写入运行日志。在 Agent 执行环境（带 `SHINKA_RESEARCH_AGENT` 标记）中，`run` 必须带所有者批准的轮次授权编号（假设、尝试次数、费用上限、允许的参数），`confirm` 必须带封存段批准编号，`--yes` 在该环境中不够；新增 `authorized-round` 模式。所有者在普通终端的手动 `run`（含自定参数）、`confirm --yes` 与原 `autonomous`、`checkpoints` 模式照旧可用，手动运行在运行日志中单独标注（所有者 2026-10-20：原有功能一项不删）。
- **研究数据服务保持只读：** 增加 Host 校验，新增只读接口提供运行日志、授权账本与待决事项。
- **本机 Agent 服务（独立进程、独立端口）：** 承担网页的全部写入——对话与批准；每次启动生成令牌，校验 Origin 与 Host；网页开着时定时运行 `watch`。
- **终端：** omp 加现有 `shinka-research` 技能，加一个定时运行 `watch` 的 shell 任务，只在有变化时唤醒模型。
- **工作台：** 导航增加 Agent 页，顶栏显示 Agent 状态与待决数，命令面板可直达；不占用检查器的右栏与手机底部抽屉（OD-11、OD-16）。

## 不做

- 窗口全部关闭后仍常驻的服务与飞书提醒（所有者选择「开着时才盯」）。
- 跨轮次自动续跑。
- 在 `LLMClient` 上另建工具调用循环；对话由 omp 承担。

## 影响

`shinka/research/cli.py`、`notebook.py`、`ui.py`，新增 Agent 服务模块，`skills/shinka-research/SKILL.md`，工作台导航、顶栏与命令面板（award-redesign 2.3 之后接入）。测试与端到端验收都不调用模型；所有者授权模型与费用后的真实运行是可选验收。
