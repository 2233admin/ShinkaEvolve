# 研究工作区页

工作项与验收真相：[GitHub #12](https://github.com/2233admin/ShinkaEvolve/issues/12)。本文供实现者和接手维护者执行，所有者仍负责最终视觉验收。实现沿用 `design.md` §7.2–7.3 的目录约定及已选定的 ops-spec 设计系统，不新增工作区数据库或方向注册表。

## 范围与存储

```text
<workspace>/
  library/                  所有方向共享的资料库
  <direction>/notebook.json  一个方向；目录名是导航 ID，标题不要求唯一
```

工作区只发现直接子目录中的有效方向。普通目录忽略；方向目录及 notebook 的符号链接不作为方向发现或读取，方向目录的 junction 等改变规范身份的别名同样排除，避免别名和资料库归属混淆。有 notebook 但内容或结果库损坏的目录保留为不可进入的错误条目，不能伪造零花费、零试验或封存状态。空工作区合法，也可以有共享资料库。

## 启动与 HTTP 契约

`shinka_research ui <workspace> [--port 8765] [--no-browser]` 直接接收工作区。传入方向目录时明确报错并提示使用父目录；不自动推断、不保留旧方向参数模式。其他研究 CLI 仍接收方向目录。

开发环境先在 `shinka/research/webui/app/` 运行 `pnpm install --frozen-lockfile`，再单独运行 `pnpm build`，不要关闭安装器的供应链校验。若安装器要求依赖脚本审批，先审阅再决定；本轮验收显式不执行依赖安装脚本，记录见 `qa.md`。然后在仓库根目录运行 `uv run shinka_research ui <workspace>`。前端构建产物仍不进入源码库。

| 入口 | 输出或行为 |
| --- | --- |
| `GET /api/workspace` | `{name, directions, library}`；摘要只读 Notebook、既有费用聚合和共享库，不调用全量方向 snapshot |
| `GET /api/snapshot?direction=<id>` | 既有方向快照形状和服务端可见性过滤；必须恰有一个非空方向参数 |
| `/?direction=<id>` | 对应方向页；ID 用 `encodeURIComponent` 编码，浏览器刷新和后退仍可访问 |
| `/` | 工作区列表；方向页提供返回工作区链接 |

成功摘要字段为 `id/direction/created/hypotheses/trials/spend_usd/budget_usd/lockbox_opened/error`，其中 `error=null`；`budget_usd=null` 表示未设预算，`lockbox_opened=null` 表示未设置数据切分。错误条目只有 `id/direction/error`。两种响应中的 `library` 都是同一工作区资料库；读页面不调用 `library.ensure`，不写研究数据。

ID 是一个真实目录名，不限 ASCII。服务端只解码查询一次，拒绝斜杠、反斜杠、点路径、绝对路径及驱动器形式，并校验规范路径仍是工作区的直接子目录。中文、空格、`+`、`%`、`#`、`&` 等合法名字可以往返；未知或越界 ID 返回 404，缺失、空值、重复参数返回 400，存在但无法读取的数据返回明确的 500 错误。

UI 在原始工作区/方向授权根下校验规范文件目标：资料库根不能搬到工作区外，库内正文、清单与原始资料不能读出资料库；方向的 notebook、假设正文、事件和实验结果不能读入相邻方向。实验根先相对方向校验，结果目录及两种数据库叶子再相对实验根校验。树服务同时校验查询派生的提示库、meta、plot 和失败提案 JSON/代码目标。静态越界链接明确失败，不把坏数据当成缺省零值；该预检查不防御并发替换链接的恶意本机进程。

## 实现取舍

| 方案 | 状态与复杂度 | 代价与边界 | 选择 |
| --- | --- | --- | --- |
| 原生文档导航 | 浏览器管理方向身份和历史，React 只保存当前方向内状态 | 切方向重新取数；不跨方向保存假设、页签选择 | 采用；全局主题继续保留 |
| SPA 路由或方向 store | 需要管理迟到请求、假设 ID 重用及各组件重置 | 无刷新切换不是本项要求 | 不采用 |
| 工作区注册表或持久 UUID | 增加索引、迁移和失效规则 | 现有数据没有该模型 | 不采用；重命名后旧链接自然 404 |

工作区和方向页均复用现有 Carbon 页签和 `LibraryTab`。工作区使用现有 Carbon 表格、token、方角和分隔线，不新增卡片网格、动画或手绘组件。每次文档只请求工作区或单方向一种视图，effect 清理取消所属请求。

上游进化树继续限制到所选方向的 `experiments`，保留 `show_private=False` 和无跨域读取头。只有方向确有实验库且被查看时才惰性创建服务，按规范方向路径缓存，用一个锁保护创建，主服务退出时关闭全部。服务数随访问过的有库方向增长，本项不增加 LRU 或空闲回收。研究层向上游程序接口传规范绝对数据库路径，使其进程级缓存键包含方向，避免相同 `h001/e01/...` 相对路径串数据。特殊目录名的上游 SQLite URI 前置修复独立跟踪于 [#13](https://github.com/2233admin/ShinkaEvolve/issues/13)，不混入本功能的上游核心 diff。

- 第 8 项先提出可替换领域评估接口设计，经所有者确认后再实现。
